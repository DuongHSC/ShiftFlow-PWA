# ShiftFlow PWA

Local-first personal shift management as an installable Progressive Web App.
Ported from the existing iOS ShiftFlow project (the behavioral reference).

- **Stack:** Vite + Vanilla TypeScript + Dexie (IndexedDB) + vite-plugin-pwa
- **Storage:** IndexedDB is the source of truth. No backend, no CloudKit, no sync.
- **Transfer:** Manual Export/Import — JSON (full backup) and CSV (calendar exchange).
- **Targets:** iPhone Safari, Windows Chrome/Edge, tablets where practical. Mobile-first.

## Requirements

- Node.js 18+ and npm.

## Commands

```bash
npm install     # install dependencies
npm run dev      # start the dev server
npm run build    # type-check + production build -> dist/
npm run preview  # preview the production build
npm test         # run the Vitest suite
```

## GitHub Pages

The Vite `base` path is configurable via the `SHIFTFLOW_BASE` env var. For a
project page at `https://<user>.github.io/<repo>/`:

```bash
SHIFTFLOW_BASE=/<repo>/ npm run build
```

For a user/organization page or a custom domain, leave `SHIFTFLOW_BASE` unset
(defaults to `/`). The GitHub Pages workflow is enabled at the repository root:
`.github/workflows/deploy-pages.yml`. It builds this app with
`SHIFTFLOW_BASE=/ShiftFlow/` for the `DuongHSC/ShiftFlow` project page.

## Architecture

```
src/
  domain/          pure logic (no storage/UI): models, resolver, rules, seed
  storage/         Dexie DB, repositories, first-run seeding
  services/        workday, tasks, events, settings, reminders + composition root
  import-export/   csv (parse/validate/export), json (full backup/restore)
  ui/              components, screens, navigation (bottom nav)
  styles/          CSS (light mode; structured for future dark mode)
  pwa/             (manifest + service worker are generated by vite-plugin-pwa)
```

Business logic never lives in UI components. `ShiftResolver` is the single
source of truth for shift schedule resolution.

## Behavior preserved from iOS

- C1–C5 resolution and the C5 special schedule (days 10–20 → 12:00–21:30).
- C5 boundary: day 9 normal, 10 special, 20 special, 21 normal (inclusive).
- WorkDay historical snapshot: config changes never rewrite existing WorkDays.
- MW / task / note independence: none of them alter resolved shift times.
- Task assignments (e.g. MW, Ticket) have no time; timed items such as meetings
  are stored separately as WorkDayEvents.
- OFF = no WorkDay record for that date.
- CSV format `Date, Shift, Task, Note` and its import/validate/export behavior.
